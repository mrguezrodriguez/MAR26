Del modelo entrenado al despliegue

Cada capa, con su herramienta. Toca una para ver qué hace.

👇 el usuario hace una petición arriba, y baja capa por capa hasta llegar al modelo

🧑 usuario
↓ petición HTTPS
☁️
Red y entrega
Cloudflare ▶
La petición llega primero aquí. Gestiona el dominio, certificado HTTPS, protección contra ataques (DDoS/WAF) y puede filtrar tráfico malicioso antes de que llegue a tu servidor. También puede cachear respuestas para que no todo tenga que llegar hasta el backend.
↓
⚙️
Orquestación
Kubernetes ▶
Decide cuántas copias de tu API tener corriendo según la carga, las reinicia si se caen, y reparte el tráfico entre ellas (load balancing). Si tu modelo recibe muchas peticiones a la vez, K8s levanta más contenedores automáticamente.
↓
📦
Contenedor
Docker ▶
Empaqueta tu código, el modelo entrenado y todas las dependencias (Python, librerías) en una imagen que corre igual en cualquier máquina. Es la unidad que Kubernetes mueve, duplica y reinicia.
↓
🔌
Servidor ASGI
uvicorn ▶
Dentro del contenedor, es lo que realmente ejecuta tu app de FastAPI y la deja escuchando en un puerto. FastAPI por sí solo no "corre" nada — necesita a uvicorn (o gunicorn) para atender peticiones de verdad.
↓
🐍
La API
FastAPI ▶
Aquí es donde escribes tú: define las rutas (@app.post("/predecir")), valida los datos de entrada, llama al modelo y devuelve la predicción en JSON.
↓
🧠
Modelo entrenado
.pkl / .h5 ▶
Se carga en memoria dentro de la app y hace la predicción con los datos que le llegaron. Esta parte ya la tienes resuelta desde el lado de data.
↓ (opcional, si necesitas guardar/consultar algo)
🗄️
Datos persistentes
Supabase ▶
Si tu API necesita guardar histórico de predicciones, usuarios o resultados, aquí es donde vive esa base de datos — fuera del contenedor, para que los datos sobrevivan aunque el contenedor se reinicie.
Regla rápida: Docker empaqueta, Kubernetes orquesta, Cloudflare protege y entrega, uvicorn ejecuta, FastAPI define la lógica, y la base de datos guarda lo que necesite sobrevivir entre peticiones. Cada herramienta resuelve un problema distinto — por eso normalmente van todas juntas, no una en lugar de otra.
