Del notebook al despliegue completo

Los pasos, y cómo queda organizado el repo al final.

📋 Pasos

1
Exportar el modelo entrenado
Desde el notebook, guarda el modelo con pickle o joblib (modelo.pkl). A partir de aquí ya no dependes del notebook.
2
Crear el proyecto de la API
main.py con la app de FastAPI, requirements.txt con las dependencias, y el modelo.pkl junto al código.
3
Escribir el endpoint de predicción
Un @app.post("/predecir") que reciba los datos (validados con Pydantic), cargue el modelo y devuelva la predicción en JSON.
4
Probar en local con uvicorn
uvicorn main:app --reload y pruebas el endpoint en /docs antes de tocar nada de despliegue.
5
Dockerizar la app
Un Dockerfile que instale dependencias y arranque uvicorn. Construyes la imagen y la pruebas en local con docker run.
6
Subir la imagen a un registro
Docker Hub, GitHub Container Registry... para que Kubernetes (o cualquier servidor) pueda descargarla.
7
Desplegar
Con Kubernetes: Deployment + Service. Más simple: un contenedor en un VPS o Render/Railway. Cloudflare delante para dominio y HTTPS.

📁 Estructura del repo

ml-api/ ├── main.py # app de FastAPI y endpoints ├── modelo.pkl # modelo ya entrenado (exportado del notebook) ├── schemas.py # modelos Pydantic para validar el input ├── requirements.txt # fastapi, uvicorn, scikit-learn... ├── Dockerfile # receta para construir la imagen ├── .dockerignore ├── .gitignore ├── tests/ │ └── test_api.py # tests del endpoint └── k8s/ # si despliegas con Kubernetes ├── deployment.yaml └── service.yaml
main.pyCrea la app, carga el modelo al arrancar (una sola vez, no en cada petición) y define @app.post("/predecir").
schemas.pyClase Pydantic con los campos que espera el modelo — FastAPI la usa para validar automáticamente lo que llega.
DockerfileParte de una imagen python:3.12-slim, instala requirements.txt, copia el código y ejecuta uvicorn main:app --host 0.0.0.0.
k8s/Solo hace falta si despliegas en Kubernetes. Para un VPS o Render/Railway, con el Dockerfile ya te vale.
El modelo nunca se reentrena dentro de la API — se carga una vez al arrancar el servidor (fuera de la función del endpoint), y cada petición solo hace modelo.predict(...). Cargarlo dentro del endpoint funcionaría, pero sería lentísimo: lo repetirías en cada petición.
