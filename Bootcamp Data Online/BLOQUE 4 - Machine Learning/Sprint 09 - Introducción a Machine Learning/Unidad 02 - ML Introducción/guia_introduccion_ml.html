Conceptos Básicos de ML
Lección 1 · 17:31
¿Qué es Machine Learning?

Machine Learning es una rama de la Inteligencia Artificial en la que los sistemas aprenden patrones a partir de datos sin ser programados explícitamente para cada tarea. En lugar de reglas escritas a mano, el algoritmo descubre la función que mapea entradas a salidas.

IA ⊃ ML ⊃ Deep Learning datos → patrón → predicción
ML vs. Programación Tradicional

En programación clásica: Reglas + Datos → Respuestas. En ML: Datos + Respuestas → Reglas (modelo). El modelo luego se aplica a nuevos datos para obtener predicciones.

Tipos de Aprendizaje

Supervisado: se entrena con datos etiquetados (input + output esperado). Ejemplos: clasificación, regresión.
No Supervisado: sin etiquetas; el algoritmo descubre estructura latente. Ejemplos: clustering, reducción de dimensionalidad.
Por Refuerzo: un agente aprende mediante recompensas y penalizaciones en un entorno.

Conceptos Clave de Vocabulario

Feature (característica): variable de entrada usada para hacer predicciones.
Label / Target: la variable que queremos predecir.
Training set: datos que el modelo ve durante el entrenamiento.
Test set: datos nunca vistos, para evaluar el modelo.
Overfitting: el modelo memoriza el training set pero no generaliza.

💡
Analogía clave: Un modelo de ML aprende como un estudiante que estudia ejemplos de examen. Si solo memoriza las respuestas (overfitting) fallará en el examen real. Si entiende el concepto (generalización), aprobará con preguntas nuevas.

⚠️
Elección del modelo: No existe el modelo "mejor" universal. La elección depende del tipo de datos, el tamaño del dataset, la interpretabilidad requerida y la métrica de negocio. Empieza siempre con el modelo más simple que resuelva el problema.
Bias vs. Variance Trade-off

Bias alto (underfitting): el modelo es demasiado simple, no capta el patrón.
Variance alta (overfitting): el modelo es demasiado complejo, aprende el ruido.
El objetivo es encontrar el punto óptimo entre ambos extremos.

Definición del Problema
¿Qué queremos predecir? ¿Qué tipo de tarea es (clasificación, regresión…)? ¿Cómo mediremos el éxito? Definir la métrica de negocio antes de escribir código.

Recolección y Comprensión de Datos
Obtener los datos crudos. Exploración inicial: df.info(), df.describe(), df.head(). Detectar volumen, tipos de variables, rango temporal, y posibles sesgos.

Tratar valores nulos (imputar o eliminar), outliers, duplicados y errores. Este paso suele consumir el 70-80% del tiempo real en proyectos.

4
Feature Engineering
Crear, transformar y seleccionar las variables que el modelo usará. Variables categóricas → encoding (One-Hot, Label). Variables numéricas → normalización/estandarización. Extraer features de fechas, texto, etc.

5
Modelado — Entrenamiento
Dividir datos en train/test (típicamente 80/20 o 70/30). Entrenar el modelo con model.fit(X_train, y_train). Usar validación cruzada (cross-validation) para mayor robustez.
train_test_splitcross_val_score
6
Evaluación y Ajuste
Clasificación: Accuracy, Precision, Recall, F1-Score, AUC-ROC, Matriz de Confusión.
Regresión: MAE, MSE, RMSE, R².
Ajustar hiperparámetros con GridSearchCV o RandomizedSearchCV.
métricasGridSearchCVhiperparámetros
7
Despliegue y Monitoreo
Serializar el modelo (joblib o pickle). Servir mediante API (Flask, FastAPI). Monitorear el rendimiento en producción y detectar data drift.
joblibAPIproducción
✅
Regla de oro del proceso: El pipeline es iterativo, no lineal. Tras evaluar el modelo es habitual volver a feature engineering o incluso a la recolección de datos. Documentar cada experimento con herramientas como MLflow o simplemente un DataFrame de resultados.

Glosario Rápido
Términos esenciales
Feature / Variable
Cada columna del dataset que se usa como entrada al modelo.
Label / Target
Variable de salida que queremos predecir.
Training set
Subconjunto de datos que el modelo ve durante el aprendizaje.
Test set
Datos reservados para evaluación final, nunca usados en entrenamiento.
Overfitting
Modelo demasiado ajustado al training; mala generalización.
Underfitting
Modelo demasiado simple; no capta los patrones del dataset.
Hiperparámetro
Parámetro de configuración del modelo (p.ej. n_estimators en Random Forest), ajustado antes del entrenamiento.
Validación cruzada
Técnica para evaluar el modelo dividiendo el dataset en k subconjuntos (folds).
Matriz de Confusión
Tabla que muestra TP, TN, FP, FN para medir el rendimiento en clasificación.
Normalización
Escalar los valores de una feature a un rango fijo (p.ej. [0, 1]).
Estandarización
Transformar features para que tengan media 0 y desviación estándar 1.
EDA
Exploratory Data Analysis: análisis inicial para comprender el dataset.
Pipeline (sklearn)
Secuencia encadenada de transformaciones + modelo que evita data leakage.
Data leakage
Filtración de información del test set al proceso de entrenamiento; invalida la evaluación.
Baseline
Modelo mínimo de referencia (p.ej. predecir siempre la clase más frecuente) contra el que comparar mejoras.
Inferencia
Usar un modelo ya entrenado para hacer predicciones sobre nuevos datos.

Cuestionario de Autoevaluación
Repaso · 15:00 estimados
ℹ️
Pulsa una opción para ver si es correcta. Usa este cuestionario para preparar el Cuestionario Introducción oficial del bootcamp.
1. ¿Cuál es la principal diferencia entre ML supervisado y no supervisado?
El supervisado necesita pares (X, y); el no supervisado solo tiene X y encuentra patrones ocultos como grupos o compresiones.
2. Un modelo que obtiene 99% de accuracy en train pero 60% en test está sufriendo…
El gap enorme entre train y test indica overfitting: el modelo memorizó los datos de entrenamiento en lugar de aprender el patrón general.
3. ¿Qué técnica convierte una variable categórica nominal (sin orden) en numérica para ML?
One-Hot Encoding crea una columna binaria por cada categoría, evitando imponer un orden artificial entre ellas.
4. ¿Cuál es la métrica MÁS adecuada para evaluar un clasificador binario con clases muy desequilibradas?
Con clases desbalanceadas la accuracy es engañosa (un modelo que siempre predice la clase mayoritaria puede tener accuracy alta). F1 o AUC-ROC consideran ambas clases.
5. ¿Por qué es importante aplicar el scaler SOLO ajustándolo con los datos de train?
Si ajutas (fit) el scaler con todo el dataset, el modelo "ve" estadísticas del test durante el entrenamiento, lo que contamina la evaluación y da resultados irrealmente buenos.
6. En scikit-learn, ¿qué método se usa para entrenar un modelo?
La API consistente de scikit-learn define fit() para entrenar, predict() para inferencia y score() para métricas básicas.
