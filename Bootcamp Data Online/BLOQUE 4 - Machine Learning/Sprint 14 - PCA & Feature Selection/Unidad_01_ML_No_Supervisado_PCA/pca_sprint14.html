Sprint 14 · Modelos No Supervisados II

PCA

Principal Component Analysis: reducir dimensiones sin perder lo esencial. PCA proyecta tus datos sobre los ejes de máxima varianza para que puedas trabajar con menos variables manteniendo la mayor información posible.

Intuición

¿Por qué reducir dimensiones?

Imagina un dataset con 50 features. Muchas están correlacionadas — si sube una, sube la otra. PCA encuentra esas redundancias y las colapsa en un número menor de componentes principales no correlacionados entre sí, que capturan la mayor parte de la varianza original.

El resultado: menos columnas, más compactas, más independientes. Los modelos entrenan más rápido, se reduce el overfitting, y la visualización 2D/3D se vuelve posible.

Maldición de la dimensionalidad — el problema

Con muchas features, los datos se vuelven dispersos. Las distancias pierden significado, los modelos necesitan exponencialmente más datos y el riesgo de overfitting explota.

PCA como solución — la respuesta

Proyecta sobre los ejes de mayor varianza. Con 2–10 componentes suele capturar el 90–99% de la varianza total, con un coste computacional mínimo.

Teoría · Álgebra lineal

Covarianza, eigenvectores y eigenvalores

PCA se basa en la matriz de covarianza de los datos. Esta matriz codifica cómo varían conjuntamente cada par de features. Los eigenvectores de esa matriz marcan las direcciones de máxima varianza; los eigenvalores cuantifican cuánta varianza hay en cada dirección.

Cov(X) = (1/n) · Xᵀ · X ← si X ya está centrada eigenvalores λ₁ ≥ λ₂ ≥ … ≥ λₚ → varianza explicada por cada PC eigenvectores v₁, v₂, …, vₚ → dirección de cada componente

Los eigenvectores son ortogonales entre sí (los componentes no están correlacionados). El primero apunta a la dirección de máxima dispersión, el segundo a la siguiente mayor, etc.

Algoritmo · Paso a paso

¿Cómo funciona PCA por dentro?

Estandarizar los datos

Centrar cada feature restando su media y dividir por su desviación típica. Sin esto, features con escalas grandes dominarían los componentes. StandardScaler antes de PCA es obligatorio si las unidades difieren.

Calcular la matriz de covarianza

Cov(X) = XᵀX / (n−1). Cada celda (i,j) indica cuánto varían juntas las features i y j. Si es positiva, suben juntas. Si es negativa, van en sentido contrario. La diagonal son las varianzas individuales.

Descomposición en eigenvectores

Factorizar la matriz de covarianza: Cov = V · Λ · Vᵀ. Los eigenvectores (columnas de V) son las direcciones principales. Los eigenvalores (diagonal de Λ) miden la varianza en cada dirección.

Ordenar y seleccionar componentes

Ordenar eigenvectores de mayor a menor eigenvalor. Elegir los k primeros que acumulen la varianza deseada (habitualmente 90–95%). Estos forman la matriz de proyección W (p × k).

Proyectar los datos

X_reducido = X · W. Cada fila sigue siendo una observación, pero ahora en el espacio de k componentes en vez de p features originales. Las columnas son los nuevos ejes PC1, PC2, …

Varianza explicada

¿Cuántos componentes elegir?

La varianza explicada por el componente i es λᵢ / Σλ. La varianza acumulada te dice qué fracción del total de información captura tu subconjunto de componentes. El criterio más común: elegir k tal que la varianza acumulada supere el 90%.

varianza_explicada[i] = λᵢ / Σλⱼ varianza_acumulada[k] = Σᵢ₌₁ᵏ varianza_explicada[i]
⚠ El scree plot y la varianza acumulada deben mirarse juntos. A veces el "codo" no está claro; en ese caso usa el criterio del 90% (o 95% si el contexto exige alta fidelidad). En clasificación, también puedes elegir k por cross-validation sobre el modelo downstream.

Interpretación

Loadings y biplot

Los loadings son las coordenadas de cada feature original en el espacio de componentes. Indican qué tanto "pesa" cada variable en cada componente. Un loading alto en PC1 significa que esa feature varía mucho a lo largo del primer eje principal.

El biplot superpone los scores de las observaciones con las flechas de loadings. Features con flechas en la misma dirección están correlacionadas; en sentido opuesto, correlación negativa.

Sklearn · API

PCA con scikit-learn

La implementación usa SVD (Singular Value Decomposition) internamente, más estable que calcular eigenvectores directamente. Mismos resultados, mejor aritmética.

from sklearn.preprocessing import StandardScaler from sklearn.decomposition import PCA import matplotlib.pyplot as plt # 1. Escalar siempre antes de PCA scaler = StandardScaler() X_scaled = scaler.fit_transform(X) # 2. Explorar cuántos componentes pca_full = PCA() pca_full.fit(X_scaled) # Scree plot plt.bar(range(1, len(pca_full.explained_variance_ratio_)+1), pca_full.explained_variance_ratio_) plt.plot(range(1, len(pca_full.explained_variance_ratio_)+1), pca_full.explained_variance_ratio_.cumsum(), marker='o', color='cyan') plt.axhline(0.90, color='gold', linestyle='--') plt.xlabel('Componente'); plt.ylabel('Varianza explicada') # 3. Ajustar con k elegido (o con umbral) pca = PCA(n_components=0.90) # automático: elige k para ≥90% X_pca = pca.fit_transform(X_scaled) print(X_pca.shape) # (n_samples, k) # 4. Ver loadings import pandas as pd loadings = pd.DataFrame(pca.components_.T, index=feature_names, columns=[f'PC{i+1}' for i in range(pca.n_components_)]) print(loadings) # 5. Biplot 2D plt.scatter(X_pca[:,0], X_pca[:,1], alpha=0.5) for i, feat in enumerate(feature_names): plt.arrow(0, 0, pca.components_[0,i]*3, pca.components_[1,i]*3, color='gold', alpha=0.8) plt.text(pca.components_[0,i]*3.1, pca.components_[1,i]*3.1, feat)

n_components — cuántos PCs

Entero: número exacto de componentes. Float entre 0 y 1: umbral de varianza acumulada (e.g. 0.95). 'mle': selección automática por criterio MLE de Minka.

explained_variance_ratio_ — resultado clave

Array con la fracción de varianza de cada componente. .cumsum() para la acumulada. Siempre graficarlo para justificar tu k.

components_ — los eigenvectores

Matriz (k × p): cada fila es un componente, cada columna el peso (loading) de una feature. Valor absoluto alto → esa feature es importante en el componente.

inverse_transform — reconstrucción

Vuelve al espacio original desde los PCs. Útil para medir el error de reconstrucción y para compresión de imágenes (ej. PCA sobre píxeles de caras).

Feature Selection

PCA vs Feature Selection: ¿cuándo usar cada uno?

PCA crea nuevas variables (combinaciones lineales). Feature Selection elige un subconjunto de las variables existentes. Son estrategias distintas con propósitos distintos.

CriterioPCAFeature Selection
InterpretabilidadBaja — los PCs no tienen nombre realAlta — sigues viendo features originales
Correlación entre featuresLa elimina por diseño (PCs ortogonales)No la resuelve
Reducción de ruidoSí — los últimos PCs suelen ser ruidoSolo si eliminas features ruidosas
Requiere escalarSí (crítico)Depende del método
LinealidadSolo captura relaciones linealesAgnóstica a la estructura
Cuándo usarMuchas features correlacionadas, necesitas comprimirNecesitas saber qué features importan
💡 En la práctica se usan juntos: Feature Selection primero (eliminar ruido obvio y features irrelevantes) y luego PCA si la dimensionalidad sigue siendo alta o hay multicolinealidad.
Limitaciones

Cuándo PCA no es la respuesta

Relaciones no lineales

PCA solo captura estructura lineal. Si los datos viven en una variedad no lineal (e.g. espiral suiza), usa Kernel PCA, UMAP o t-SNE.

Necesitas interpretabilidad

"PC1 es una combinación de 20 variables" no le sirve al cliente. Si debes explicar el modelo, Feature Selection o modelos con importancia de features son mejores.

Outliers graves

PCA clásico es sensible a outliers (maximiza varianza, que los outliers inflan). Usar Robust PCA o escalar con RobustScaler antes.

Datos categóricos

PCA asume variables continuas. Para categorías usa MCA (Multiple Correspondence Analysis) o encoding adecuado antes.
