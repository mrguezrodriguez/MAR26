Cheatsheet: Transfer Learning y Fine-Tuning (Keras)

Guion para reutilizar una CNN preentrenada en ImageNet sobre tu propio dataset, comparándola contra una CNN ad-hoc.

0. Transfer learning vs fine-tuning: la diferencia real

Ambos parten exactamente del mismo código: cargar el modelo base, quitarle la cabeza (include_top=False) y ponerle una tuya. La única diferencia está en una línea:

# Transfer learning: el cuerpo se queda como está
for layer in base_model.layers:
    layer.trainable = False

# Fine-tuning: se omite ese bucle (o se descongela después de un primer entrenamiento)
Transfer learningFine-tuning
Qué se entrenaSolo la cabeza nuevaCabeza + cuerpo preentrenado
Params entrenablesPocos (los de tu cabeza)Casi todos (millones)
VelocidadRápidoMucho más lento
Cuándo usarloDataset pequeño o parecido a ImageNetCuando el transfer se queda corto y tienes datos/tiempo de sobra
RiesgoTecho de accuracy más bajoSobreajuste si el dataset es muy pequeño

Dato curioso: aunque pongas trainable=True en todo el modelo, siempre queda un resto de parámetros "non-trainable" (del orden de decenas de miles). Son las medias/varianzas internas de las capas BatchNormalization: nunca se entrenan por gradiente, se actualizan de otra forma durante el fit.

1. Elegir el modelo preentrenado

El error más caro de esta práctica: usar el preprocesado que no toca. Cada familia de modelos se entrenó con una normalización distinta en ImageNet. Si le das píxeles en rango 0-255 (o 0-1) a un modelo que espera -1 a 1, no falla con un error — simplemente entrena mal, porque los pesos preentrenados de la primera capa "esperan" ver ciertos rangos de entrada.

# Para MobileNetV2 e InceptionV3
X_train = (X_train / 127.5) - 1.0
X_test = (X_test / 127.5) - 1.0

# Para VGG/ResNet, mejor usar la función oficial de Keras en vez de hacerlo a mano:
from keras.applications.vgg19 import preprocess_input
X_train = preprocess_input(X_train)

2. Cargar el modelo base sin cabeza

from keras.applications import InceptionV3

base_model = InceptionV3(include_top=False, weights='imagenet', input_shape=(TAM, TAM, 3))

include_top=False le dice a Keras que no incluya la parte final de la red (la que clasifica en las 1000 clases de ImageNet). Te quedas solo con el "cuerpo" — todas las capas convolucionales que extraen bordes, texturas y formas — y le pones tú tu propia cabeza, adaptada a tus clases.

3. Poner tu cabeza (máx. 2 densas ocultas + salida)

def prepare_model(base_model=base_model):
    x = keras.layers.Flatten()(base_model.output)
    x = keras.layers.Dense(512, activation='relu')(x)
    x = keras.layers.Dropout(rate=0.5)(x)

    # Binaria: 1 neurona + sigmoid. Multiclase: N neuronas + softmax
    x = keras.layers.Dense(1, activation='sigmoid')(x)

    model = keras.Model(base_model.input, x)
    model.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])
    return model

model = prepare_model()
model.summary()

Revisa el summary(): en transfer learning, Trainable params debe ser solo el tamaño de tu cabeza (unos pocos millones o menos). Si sale igual al total, olvidaste congelar.

4. Entrenar y evaluar (igual en transfer y fine-tuning)

early_stopping = keras.callbacks.EarlyStopping(monitor="val_loss", patience=5, restore_best_weights=True)

history = model.fit(X_train, y_train,
                    batch_size=32,
                    validation_split=0.2,
                    epochs=30,
                    callbacks=[early_stopping])

from sklearn.metrics import classification_report, ConfusionMatrixDisplay

probabilidades = model.predict(X_test).flatten()
predicciones = (probabilidades > 0.5).astype(int)

print(classification_report(y_test, predicciones, target_names=["clase0", "clase1"]))
ConfusionMatrixDisplay.from_predictions(y_test, predicciones, display_labels=["clase0", "clase1"])

Libera memoria entre un entrenamiento y el siguiente (vas a repetir esto varias veces: transfer, fine-tuning, augmentation):

5. Con ImageDataGenerator: la trampa del orden de clases

Si usas flow_from_dataframe para el augmentation, Keras construye su propio mapa de clases → índice, en orden alfabético, sin preguntarte. Si tú ya habías creado tu propio diccionario a mano, lo más probable es que no coincidan.

train_generator = train_datagen.flow_from_dataframe(
    train_df, x_col='filename', y_col='category',
    target_size=(TAM, TAM), class_mode='sparse', batch_size=batch_size
)

# Este es EL mapa real que usó el generador para entrenar:
train_generator.class_indices

Síntoma: el modelo va bien en train y en validación, pero se desploma contra tu X_test/y_test manual (accuracy cercano al azar o incluso peor). No es que el modelo no haya aprendido — es que tu y_test numérico usa un mapa de clases distinto al que usó el generador para entrenar.

Arreglo: reconstruye y_test_num usando el mapa del generador, no el tuyo:

y_test_num = np.array([train_generator.class_indices[etiqueta] for etiqueta in y_test])

6. Comparar contra tu CNN ad-hoc

El punto de todo el ejercicio no es "conseguir el número más alto", es entender el trade-off. Cosas a mirar, no solo el accuracy global:

  • ¿Qué clases mejoran y cuáles empeoran? Un modelo puede ganar en total y aun así ser peor en una clase concreta que tu CNN.
  • ¿Cuánto ha costado la mejora? Fine-tuning suele ganar unos puntos más que transfer learning, pero a cambio de mucho más tiempo de entrenamiento (millones de parámetros más que actualizar).
  • Matriz de confusión lado a lado. Busca si los dos modelos confunden las mismas parejas de clases o si cambian los errores.

Guion mínimo

  1. Elegir modelo según potencia del ordenador y mirar su tamaño mínimo de entrada
  2. Cargar datos con el mismo cargar_imagenes de siempre, ajustando TAM
  3. Preprocesar con la normalización correcta para ese modelo (no la que uses siempre)
  4. Transfer learning: cargar base + congelar + cabeza (máx. 2 densas + salida) → entrenar → evaluar
  5. Fine-tuning: mismo código sin congelar → entrenar (más lento) → evaluar
  6. Comparar ambos entre sí y contra la CNN ad-hoc: accuracy, report, matriz de confusión
  7. Extra: repetir transfer learning con ImageDataGenerator, cuidado con class_indices
