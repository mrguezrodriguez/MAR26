01 · Panorama

Introducción — Ejemplo

Keras es la API de alto nivel de TensorFlow para construir y entrenar redes neuronales. Su filosofía es que definir una red se parezca lo más posible a describirla con palabras: "una capa de 64 neuronas, luego otra de 32, luego la salida" — sin tener que programar a mano las matemáticas de cada neurona.

Analogía

Si backpropagation y gradient descent son el "motor" del coche, Keras es el volante y el salpicadero: te da controles simples (Dense(64), model.fit()...) para dirigir todo ese motor matemático sin tener que construirlo pieza a pieza.

El flujo de trabajo típico en Keras

1. Definir topología
→
2. Compilar
→
3. Entrenar (fit)
→
4. Evaluar
→
5. Predecir

Un ejemplo mínimo de principio a fin, para tener el mapa completo antes de entrar en detalle en cada paso:

from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense

# 1. Definir la topología (arquitectura)
model = Sequential([
    Dense(64, activation='relu', input_shape=(10,)),
    Dense(32, activation='relu'),
    Dense(1, activation='sigmoid')  # salida binaria
])

# 2. Compilar: cómo va a aprender
model.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])

# 3. Entrenar
model.fit(X_train, y_train, epochs=20, batch_size=32)

# 4. Evaluar
model.evaluate(X_test, y_test)

# 5. Predecir
model.predict(X_new)

Cada una de estas cinco líneas de intención corresponde a una de las píldoras siguientes. Vamos a desgranarlas.

02 · Arquitectura

Construcción de Topología

En Keras hay dos formas principales de definir la arquitectura de una red:

Sequential API

La forma más simple: apilas capas una detrás de otra, en orden, como una lista. Sirve para la mayoría de arquitecturas "lineales" (una entrada, una salida, sin ramificaciones).

model = Sequential([
    Dense(64, activation='relu', input_shape=(10,)),
    Dense(32, activation='relu'),
    Dense(1)
])

Functional API

Más flexible: defines cada capa como una función que se aplica sobre la anterior, y luego declaras el modelo indicando input y output. Necesaria para arquitecturas con varias entradas/salidas, ramificaciones, o conexiones que "saltan" capas.

from tensorflow.keras.layers import Input, Dense
from tensorflow.keras.models import Model

inputs = Input(shape=(10,))
x = Dense(64, activation='relu')(inputs)
x = Dense(32, activation='relu')(x)
outputs = Dense(1)(x)

model = Model(inputs=inputs, outputs=outputs)
¿Cuál usar?

Para la inmensa mayoría de tus proyectos de bootcamp, Sequential es suficiente y más legible. El Functional API se reserva para arquitecturas más avanzadas (por ejemplo, redes con dos ramas de entrada distintas que se combinan más adelante).

La forma de entrada: input_shape

Solo la primera capa necesita saber la forma de los datos de entrada (cuántas features tiene cada ejemplo). Las capas siguientes ya "saben" su input porque es el output de la capa anterior — Keras lo infiere automáticamente.

03 · Configuración de capas

Inicializadores y Capas

Tipos de capas más comunes

CapaPara qué sirve
DenseCapa totalmente conectada — la básica del MLP
DropoutApaga aleatoriamente un % de neuronas durante entrenamiento (regularización)
BatchNormalizationNormaliza las activaciones entre capas, estabiliza el entrenamiento
FlattenConvierte datos multidimensionales (ej. imagen 2D) en un vector plano
InputPunto de entrada del modelo (solo en Functional API)
from tensorflow.keras.layers import Dense, Dropout, BatchNormalization

model = Sequential([
    Dense(64, activation='relu', input_shape=(10,)),
    BatchNormalization(),
    Dropout(0.3),  # apaga el 30% de las neuronas
    Dense(32, activation='relu'),
    Dense(1, activation='sigmoid')
])

Inicializadores de pesos

Recordando el HTML anterior: los pesos no pueden inicializarse todos igual. Keras usa por defecto glorot_uniform (también llamado Xavier), pero puedes especificar otros:

Dense(64, activation='relu', kernel_initializer='he_normal')
InicializadorCuándo se usa típicamente
glorot_uniform (Xavier)Por defecto en Keras; buena opción general con sigmoid/tanh
he_normalRecomendado cuando se usa ReLU en las capas
zerosHabitual para inicializar el bias (no los pesos)
No es algo que sueles tocar

En la práctica, rara vez cambiarás el inicializador manualmente — los valores por defecto de Keras funcionan bien en la mayoría de casos. Conviene entender que existe, más que memorizar cuándo cambiarlo.

04 · Configuración de aprendizaje

Funciones de Activación y Optimizador

Activaciones en Keras

Se pasan como string dentro de la capa, o como capa aparte si necesitas más control:

Dense(64, activation='relu')          # forma más común

# equivalente, como capa separada
from tensorflow.keras.layers import Activation
Dense(64)
Activation('relu')
String en KerasDónde se usa normalmente
'relu'Capas ocultas
'sigmoid'Salida — clasificación binaria
'softmax'Salida — clasificación multiclase
None / 'linear'Salida — regresión (sin activación, valor libre)

Optimizadores en compile()

Se especifican al compilar el modelo. Puedes pasarlos como string (config por defecto) o como objeto (para ajustar hiperparámetros como el learning rate):

# forma simple
model.compile(optimizer='adam', loss='mse')

# forma con control del learning rate
from tensorflow.keras.optimizers import Adam
model.compile(optimizer=Adam(learning_rate=0.001), loss='mse')
Idea clave

compile() es donde le dices a la red cómo va a aprender: qué optimizador (cómo ajusta los pesos), qué loss (cómo mide el error) y qué métricas quieres monitorizar (accuracy, mae...) mientras entrena. No entrena nada todavía — solo configura el entrenamiento.

05 · Ejecución

Entrenamiento

El entrenamiento en sí ocurre con model.fit():

history = model.fit(
    X_train, y_train,
    epochs=50,
    batch_size=32,
    validation_data=(X_val, y_val)
)
ParámetroQué controla
epochsCuántas veces pasa por todo el dataset de entrenamiento
batch_sizeCuántos ejemplos procesa antes de actualizar los pesos
validation_dataDatos aparte para medir el rendimiento en cada epoch sin entrenar con ellos (detecta overfitting)
validation_splitAlternativa: reserva automáticamente un % de X_train como validación

El objeto history

fit() devuelve un objeto con la evolución del loss y las métricas en cada epoch — es lo que normalmente se grafica para ver si el modelo converge bien o está sobreajustando:

history.history['loss']        # loss en train, por epoch
history.history['val_loss']    # loss en validación, por epoch
Cómo leerlo

Si loss baja pero val_loss empieza a subir de nuevo tras cierto punto, es la señal clásica de overfitting: el modelo está memorizando el train set en vez de generalizar. Es el mismo patrón que ya conoces de train/test en ML clásico, solo que aquí lo ves epoch a epoch.

06 · Validación

Evaluación

loss, accuracy = model.evaluate(X_test, y_test)
print(f"Loss: {loss}, Accuracy: {accuracy}")

evaluate() calcula el loss y las métricas definidas en compile(), pero sobre datos que el modelo no ha visto durante el entrenamiento — igual que el .score() o el classification_report que ya usas con sklearn.

Predicciones individuales

predictions = model.predict(X_new)
Cuidado con clasificación

En clasificación, predict() devuelve probabilidades (por la activación sigmoid/softmax), no la clase directamente. Necesitas un paso extra para convertirlas en etiquetas:

# binaria
clases = (predictions > 0.5).astype("int32")

# multiclase
import numpy as np
clases = np.argmax(predictions, axis=1)
07 · Caso práctico

Modelado de Regresión

Para regresión (predecir un número continuo, como el precio de una reserva), la arquitectura cambia en dos puntos clave respecto a clasificación:

Capa de salida

1 neurona, sin activación (o 'linear') — el output puede ser cualquier número real, no una probabilidad entre 0 y 1.

Función de pérdida

MSE o MAE en vez de crossentropy — mide distancia numérica, no error de clasificación.

model = Sequential([
    Dense(64, activation='relu', input_shape=(10,)),
    Dense(32, activation='relu'),
    Dense(1)  # sin activación: salida = número real
])

model.compile(
    optimizer='adam',
    loss='mse',       # Mean Squared Error
    metrics=['mae']  # Mean Absolute Error, más interpretable
)
Idea clave

La arquitectura de una red para regresión y otra para clasificación es prácticamente idéntica en las capas ocultas — lo único que cambia sistemáticamente es la capa de salida y la loss function, exactamente igual que decidías RandomForestRegressor vs RandomForestClassifier en sklearn.

08 · Utilidades

Elementos Adicionales

Callbacks

Funciones que se ejecutan automáticamente durante fit(), en momentos concretos (final de cada epoch, por ejemplo). Los más usados:

from tensorflow.keras.callbacks import EarlyStopping, ModelCheckpoint

early_stop = EarlyStopping(
    monitor='val_loss',
    patience=5,          # espera 5 epochs sin mejora antes de parar
    restore_best_weights=True
)

checkpoint = ModelCheckpoint(
    'mejor_modelo.keras',
    save_best_only=True
)

model.fit(X_train, y_train, epochs=100,
          validation_data=(X_val, y_val),
          callbacks=[early_stop, checkpoint])
CallbackQué hace
EarlyStoppingDetiene el entrenamiento si la métrica de validación deja de mejorar
ModelCheckpointGuarda el modelo automáticamente cuando mejora
ReduceLROnPlateauReduce el learning rate si el entrenamiento se estanca

Guardar y cargar modelos

model.save('mi_modelo.keras')

from tensorflow.keras.models import load_model
modelo_cargado = load_model('mi_modelo.keras')

model.summary()

Imprime la arquitectura completa: capas, forma de salida de cada una, y número de parámetros entrenables. Es el primer comando que se ejecuta después de definir cualquier modelo, para verificar que la topología es la esperada.

model.summary()

Para no perder de vista

Todo el "vocabulario Keras" (Sequential, compile, fit, evaluate, predict) es solo una capa de sintaxis sobre los conceptos que ya viste en el HTML de teoría: topología, activaciones, backprop, gradient descent. Keras no introduce ideas nuevas — te da comandos cortos para expresar esas ideas sin escribir las matemáticas a mano.
